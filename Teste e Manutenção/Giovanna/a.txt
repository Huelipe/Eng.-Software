# Identificação e Correção de Bugs

## [Seu Nome]:

### Bug 1: Mistura de tipos na listagem

**Descrição:**
Em versões anteriores, ao chamar o método de recuperação de histórico, o sistema retornava a lista completa de transações sem filtrar pelo `tipo` da movimentação, fazendo com que gastos aparecessem na tela de ganhos e vice-versa.

**Arquivo:** `Pedro/Facade.py` (Lógica de Negócio)

**Método:** `get_historico_receitas()` e `get_historico_despesas()`

**Problema:** Retorno direto da lista `self.transacoes` sem list comprehension ou filtro condicional.

➡️ **Resultado:** TESTE FALHOU (Anteriormente)

#### Análise da Causa

A função original apenas devolvia o objeto de armazenamento bruto:

```python
return self.transacoes  # Retornava tudo sem criterio
```

Isso causava inconsistência visual nas telas `ReceitasScreen` e `DespesasScreen`.

#### Correção Implementada

Foi implementada uma filtragem rigorosa no backend antes de entregar os dados para a interface:

```python
# Correção no Facade para filtrar receitas
return [t for t in self.transacoes if t.tipo == 'receita']

# Correção no Facade para filtrar despesas
return [t for t in self.transacoes if t.tipo == 'despesa']
```

#### Resultado Após Correção

Rodando o cenário de teste **CT06** novamente:

1.  Adicionado Despesa "Teste Erro".
2.  Aberto tela de Receitas.
3.  Item "Teste Erro" não apareceu.

➡️ **Cenário passou ✔**

# ✨ Documentação da Funcionalidade de Listagem

Esta seção detalha a implementação das telas de consulta de movimentações.

## Funcionalidade adicionada por [Seu Nome]

#### Segregação Lógica de Movimentações

Foi implementada a separação lógica das transações no momento da leitura do arquivo JSON.

  * O sistema agora classifica cada entrada como "receita" ou "despesa" baseada na flag `tipo` salva no JSON `movimentacoes.json`.
  * Isso impede que erros de interface mostrem dados incorretos, pois o filtro ocorre na camada de dados (Facade).

#### Telas de Consulta Dedicadas (`ReceitasScreen` e `DespesasScreen`)

Foram criadas duas telas distintas no `main_kivy.py` para melhor experiência do usuário:

1.  **ReceitasScreen:**

      * Itera apenas sobre transações positivas.
      * Exibe gráfico de pizza (Pie Chart) exclusivo para categorias de entrada.
      * Calcula o total de ganhos dinamicamente.

2.  **DespesasScreen:**

      * Itera apenas sobre transações negativas.
      * Exibe gráfico de pizza mostrando onde o usuário mais gastou.
      * Converte valores negativos para absolutos (positivos) visualmente para facilitar a leitura no gráfico.

#### Tratamento de Listagem Vazia

Foi adicionada uma verificação visual nas telas. Se não houver itens:

  * O gráfico é ocultado/limpo.
  * Uma mensagem amigável ("Nenhuma receita/despesa registrada") é exibida ao invés de uma tela em branco ou erro de código.
